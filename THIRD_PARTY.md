## Ideas and formats we followed (no code copied)

- The 4-bit block layout ("q4": 32 weights per block, one scale, values −8..7) follows
  the Q4_0 format idea from ggml/llama.cpp (MIT). It was implemented from scratch here.
- The byte-to-character table used to read Qwen3's vocabulary is the standard byte-level
  BPE mapping introduced with GPT-2. It was implemented from scratch here.
- The engine's tokenizer reads the model's own `tokenizer.json` and follows the same
  steps as Hugging Face `tokenizers` for Qwen models (split pattern, byte-level mapping,
  BPE merges). It was implemented from scratch here and is checked against Hugging Face's
  output by `engine/tools/verify_tokenizer.py`.
- The chat server speaks the request and response format of OpenAI's Chat Completions
  API, so that existing clients can connect. No OpenAI code is used.
- The `.safetensors` reader (`trace/st_reader.py`) follows the public safetensors file
  format specification. It does not use the safetensors library.

## Data

- `engine/src/unicode_letters.rs` lists which characters are letters (Unicode general
  category L). It is generated by `engine/tools/gen_unicode.py` from the Unicode
  Character Database as shipped with Python. Unicode data: Copyright © Unicode, Inc.,
  distributed under the [Unicode License v3](https://www.unicode.org/license.txt).
- `trace/corpus.txt` is original text written for this project (chats, code, short
  articles and stories), Apache-2.0 like the rest of the repository. It is used to measure
  perplexity and to make the benchmark prompt.
